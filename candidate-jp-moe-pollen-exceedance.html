jp-moe-pollen-exceedance

investigating · JP 19:50 UTC

The question

what a model is asked to predict

For a Hanako-san automatic pollen-counter station (KH-3000 volumetric counter, hourly grains/m3), given that station's own hourly pollen counts through the end of day t-1 and the paired AMEDAS hourly weather through the same instant (plus calendar and station identity), will the station's day-t 24-hour total pollen count exceed a high-pollen threshold? RETROSPECTIVE BENCHMARK: the MOE terminated the automatic network on 2021-12-24, so this is a historical benchmark task on a closed archive, not an operational forecasting product; live pollen feeds are now private (tenki.jp, Weathernews) and are not used.

What you predict

target definition

Binary: sum of the station's 24 hourly counts on day t (JST) >= threshold, with a censoring rule excluding day t from scored rows when fewer than 20 of 24 hourly values are valid (valid = non-missing per the in-file codes: blank = unobserved/comms outage, -9996 = other/unatural removed, -9997 = Asian-dust interference, -9998 = snow interference). Threshold OURS (construction decision): the archive publishes no daily category table for the automatic counters (the real-time site's 4-level colour scheme is not documented as numeric daily totals in the archive), so a base rate at a candidate threshold (e.g. a JWA-style daily-total level) is measured at construction, not asserted now. Units: grains/m3 (個/m3), volumetric KH-3000 counts; the MOE labels the real-time display 'スギ花粉数' ('for the time being, sugi pollen count') per press 4673 - whether the archive column is sugi-only or sugi+hinoki total is a documentation check at construction (single count column per station per file; no taxon split in the files). Label source column (day-t counts) is excludable from features by construction (features are strictly <= t-1).

When the prediction is made

the information cut-off

Prediction instant: 00:00 JST on day t (equivalently the end of day t-1). Features: hourly pollen counts at the station and paired AMEDAS weather, all timestamps <= 23:59 JST day t-1; no same-day values. Historical real-time availability: while it ran, the system published hourly updates (MOE press 4673: '1時間ごとに更新', real-time web display), so an operational user at day t-1 23:59 had all feature values. VINTAGE CAVEAT (recorded, not resolved): the archive is a post-season cleaned vintage - the in-file code -9996 explicitly marks values removed after comparing '前後の時間や周辺観測値' (neighbouring hours/stations), i.e. post-hoc quality edits a real-time user would not have had; blank/-9997/-9998 mark comms outage/Asian dust/snow outages. The task therefore claims NO historical operational availability and is labelled retrospective; the as-of policy is 'archive vintage, as downloaded 2026-10-28'. Station-eligibility for scored rows must be computed from a trailing pre-instant window (e.g. valid days in the last 14 days before t), never from full-season validity, to avoid future-conditioned inclusion.
