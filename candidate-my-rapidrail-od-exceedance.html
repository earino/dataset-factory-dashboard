The question

what a model is asked to predict

At 07:00 Asia/Kuala_Lumpur on operating day T, using only the published origin-destination ridership history dated T-2 and earlier (the publication lag is one day, so day T-1's rows are not yet available at the instant - measured, see prediction_time), predict whether a given station-pair's ridership on day T (00:00-23:59 local) will exceed a fixed reference threshold for that pair. A useful prediction supports Rapid Rail's operational planning at the day-ahead horizon: train frequency, staff/crowd-control deployment at interchange stations, and event-day capacity decisions for the ~1M daily trips on the network.

What you predict

target definition

Binary label per (origin, destination, day T): pair ridership on day T >= a fixed pair-specific reference threshold (construction selects: per-pair training-window percentile, e.g. p90, or a small set of absolute thresholds; candidate thresholds recorded from measured pair-year series in probe/pair_blocks_2024.json). Source column: 'ridership' (integer trips, publisher-documented as trips not necessarily passengers); it is the label source and is excludable from shipped features (shipped features are the SAME column's values at dates <= T-2 plus calendar - the label is its day-T value, which postdates the instant). Population: all ordered station pairs on the network with an active block in the source, excluding (a) rows with origin or destination 'A0: All Stations' (pseudo-station aggregate/censored rows, measured station-scale magnitudes ~4.4k/day, semantics to be verified against pair sums at construction), and (b) pairs whose destination is a Putrajaya Line station other than PYL03/PYL04 (32/34 PYL station codes never appear as destinations - confirmed by my own 2024-edition sampling AND by a public data-request thread id 216 dated 2026-10-24; censoring, not zero demand). Zero-ridership days are published as rows with value 0 (29.3% of pair rows on a sampled Saturday), so observed absence is distinguishable from missing data.

When the prediction is made

the information cut-off

07:00 Asia/Kuala_Lumpur on target day T, before the operating day begins. Every feature is a ridership row dated <= T-2, taken from the frozen annual edition (completed years) or the pinned current-year snapshot; all four source columns (origin, destination, date, ridership) are individually documented by the publisher (dataset page 'fields' metadata, measured 2026-11-07), and no undocumented column is used. Publication calendar is the publisher's own: the dataset page carries data_as_of 2026-11-06 23:59, last_updated 2026-11-07 16:03, next_update 2026-11-08 22:00, and the storage file rapidrail_2026_daily.csv (Content-Length 318,772,855) was last modified 2026-11-07 08:03:16 GMT with its last data row dated 2026-11-06 - a measured one-day publication lag. Frozen annual editions 2023 (374,488,341 B, Last-Modified 2026-09-21), 2024 (375,944,306 B, 2026-09-23), 2025 (309,579,953 B, 2026-04-02) pin the completed years; the 2026 edition updates daily and must be digest-pinned at build. Calendar features (day-of-week, month, elapsed-day) are available at any instant. This is a current-compilation retrospective: per-row historical vintages are not published, and no operational point-in-time reproducibility of past values is claimed - the same posture as ab-wildfire-ia-escape, to be stated in quality.json.evaluation_contract.
