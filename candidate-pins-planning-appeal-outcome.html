ready · GB 17:50 UTC

The question

what a model is asked to predict

For a planning-permission-family appeal (PINS casework type 'Planning Appeal' or 'Householder (HAS)') validated by the Planning Inspectorate, will the final decision be 'Allowed' rather than 'Dismissed', given only what is known at validation: casework type, LPA name and ONS code, LPA decision date, received date, procedure (written representations / hearing / inquiry), development type, appeal type reason and type-detail, site descriptors (area, floorspace, number of residences, green belt, agricultural holding, listed-building setting, conservation area, flooding issue, AONB, SSSI indicators), LPA application reference, and enforcement grounds where applicable?

What you predict

target definition

Binary from the publisher's Decision field (documented data quality 'Good'): positive = 'Allowed', negative = 'Dismissed'. Pre-specified eligibility rule: labelled population = s78_core casework types with Decision in {Allowed, Dismissed}; 'Split Decision' (1,350 5-yr / 1,440 older, all types) and 'Allowed in part' rows are excluded from the core task rather than coerced (recorded masses; a variant may map split->positive). Excluded outcomes (measured, all types): Unknown 3,186+1,969, No Decision Code Associated 148+72, Invalid 237+136, Turned Away 9+11, Appeal Withdrawn 243+169, missing 178+600. Enforcement/RoW/TPO/high-hedges casework uses a different outcome vocabulary (Notice upheld / varied and upheld / quashed) and is out of scope. Censoring is stated: the database contains DECIDED cases only (publisher: in-progress, withdrawn and turned-away cases are not included), so the population is outcome-conditioned by construction; the task is 'among validated appeals that reach a PINS decision, which succeed', not 'among all validated appeals'. Decision and Decision Date columns are excluded from shipped features.

When the prediction is made

the information cut-off

00:00 Europe/London on the appeal's Valid Date (the date PINS validated the case; present on 100% of the 186,785 measured decided rows). All outcome events (case start, allocation, hearing/inquiry, decision) postdate the instant; measured valid->decision lag is 91-365 days for 74% of cases. Every feature field is recorded from the appeal submission/registration and is documented by the publisher with a per-field data-quality grade (Appeals Data: Data notes and guidance). Post-instant fields are excluded by contract: Inspector Name (allocation after validation; publisher also warns apparent per-inspector outcome patterns are allocation artefacts), Start Date, Jurisdiction (mutable by recovery/derecovery), Date Recovered / Date Not Recovered / Call In Date, Redetermined, Bespoke, and the Decision/Decision Date columns themselves. Costs Applied for Indicator is treated as verify-at-construction (a costs application can be lodged after validation). This is a fixed RETROSPECTIVE benchmark over the current published files: the publisher revises the rolling database between editions ('data can change between different publications of this data set'), so historical operational as-of claims would need vintage evidence beyond this record (the update log documents monthly-to-quarterly publication since March 2018, so web-archive vintages are provable if a historical-availability claim is ever wanted).
