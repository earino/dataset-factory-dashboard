The question

what a model is asked to predict

At a consumer-product recall's first publication on the METI recall register (リコール日/掲載日, Asia/Tokyo), predict whether the register will later record a substantive lifecycle update on that recall - 対象追加 (affected-scope addition), 型番追加 (model addition), 品番追加・対象期間拡大 (item/period expansion) or 対策内容更新 (countermeasure change) - within a pre-registered window, using only information published at the first instant (product sub-category, product name, implementing business incl. domestic/overseas-importer marker, initial date, sales period, affected-unit count, hazard/remedy fields - per-field availability to be verified on the detail pages). Cosmetic updates (問い合わせ先/電話番号/受付時間/URL更新) are excluded from the label. A useful prediction supports METI/CAA post-publication scrutiny triage and the business's own scope review: an under-scoped recall leaves hazardous units in homes and forces repeat consumer notices.

What you predict

target definition

DRAFT: binary label = the same register row later carries a second date plus a substantive update marker (対象追加 / 型番追加 / 品番追加・対象期間拡大 / 対策内容更新) within the pre-registered window (365-day primary variant; the update-lag distribution must be measured from the full register first - measured examples span 42 days to ~4.9 years, so the window choice changes the base rate materially and must be set from full-register counts, not this sample). Label source columns (the second date and marker) are excludable from what ships. Population: every recall published on the METI register since 2007-05-14, one row per recall publication; eligibility is publication-based, never outcome-based.

When the prediction is made

the information cut-off

The recall's first publication instant on the METI register - the row's リコール日 as published, read as Asia/Tokyo. The register's own index states the ministry publishes recall information as a rule ('原則経済産業省のWebページで公表', measured 2026-11-07) and announces on X at posting. At-publication feature set verified on one modern detail page (measurements.detail_page_schema_2026_11_07): product codes (EAN/batch), 販売期間 sales period, 対象台数 affected units, remedy, reason, business + 法人番号, plus the register row's own fields (sub-category, red-text major-accident marker, overseas-business marker). AVAILABILITY CAVEAT (measured): updated rows link to the CURRENT detail-page revision (measurements.detail_page_revision_finding), and the register revises entries in place (two-date markers), so per-row feature values as of each row's own publication day need Wayback vintages or must be restricted to register-row stable fields; the task is a current-compilation retrospective (explicit evaluation_contract assumptions) unless the Wayback probe bounds historical availability. Detail-page field sets across eras (pre-2015 pages, category variations) still need the bounded verification named in next_action.
