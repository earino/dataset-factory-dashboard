iaac-registry-assessment-termination

investigating · CA 21:50 UTC

The question

what a model is asked to predict

For a project assessment posted to the Canadian Impact Assessment Registry, at its registry start date, will the assessment process terminate before any determination or decision is issued (proponent withdrawal / process termination), rather than run to a determination?

What you predict

target definition

Binary: the assessment's terminal state is 'Terminated' (MapServer layer 2 membership; registry page 'Assessment status: Terminated' plus a dated termination line in 'Latest update', e.g. proj 81027 'January 18, 2022 - The assessment process has been terminated') vs 'Completed' with a dated determination (e.g. proj 84411 'August 29, 2023 - ... determined that the project is not likely to cause significant adverse environmental effects'). Label source columns: project_state_en, the page Latest-update text/date and Assessment status - all excluded from shipped features. Assessments still 'In progress' at fetch time are censored and must be handled by an explicit censoring rule, not dropped silently.

When the prediction is made

the information cut-off

The assessment's registry start date (published per project on the registry page and in the MapServer layer as start_date). Features available at that instant: the inventory attributes published with the posting (project category, province, responsible authority(ies), location type, coordinates, description text, start date). The terminal state and its dated event (Latest update line: termination date, or Notice-of-Determination date + outcome wording) and the layer's current project_state_en/updated_at are post-hoc label sources and never ship as features. The registry is a live current archive: no historical vintages of pages are published, so the task is retrospective-within-current-archive, anchored on the dated events the current pages preserve; it cannot claim historical operational availability.
